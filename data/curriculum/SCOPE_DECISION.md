# Scope Decision: CSE, EEE, ECE, and E&I — all four engineering branches now covered

**Updated decision:** all four BITS Hyderabad engineering branches relevant to this programme (CSE, EEE, ECE, E&I) are now encoded to the same standard: real bulletin-sourced Discipline Core credits (each independently verified to match the bulletin's own stated unit total exactly), real Discipline Elective pools, and prerequisites from the same cross-verified KB.

## Verification results, all four branches

| Branch | Discipline Core | Match to bulletin's stated total | Discipline Electives added |
|---|---|---|---|
| cse | 14 courses | Exact (48/48) | 12 real courses, 35 credits available |
| eee | 14 courses | Exact (48/48) | 11 real courses, 35 credits available |
| ece | 14 courses | Exact (48/48) | 9 real courses, 28 credits available |
| e_and_i | 14 courses | Exact (48/48) | 10 real courses, 32 credits available |

Every branch's Discipline Core unit total was independently computed from its own encoded courses and checked against the bulletin's own stated figure for that branch — not assumed to match because the pattern held for `cse`. All four matched exactly.

## What's still NOT done, honestly

- None of `ece`/`e_and_i`'s data has been cross-checked against the TTD-authoritative prerequisite table (`Pre-requisite_November_2025.pdf`) the way `cse`'s 27 scope courses were — that cross-check found 100% agreement for `cse`, but hasn't been repeated here. The data comes from the same already-verified KB, so it's not ungrounded, just not independently re-confirmed against the primary source a second time.
- Minors other than `data_science` are not encoded.
- No branch's full elective pool is exhaustively encoded — each branch has a real, usable, but partial subset of its actual elective list (the bulletin's lists run considerably longer than what's encoded here). Expanding any branch's elective pool further just means repeating the same sourcing method already demonstrated.

## History

This decision previously limited scope to CSE+EEE only, citing the proposal's "focused scope beats shallow coverage of several" principle (§3). That principle was honored at each step: `ece` and `e_and_i` were only added once each individually passed the same verification bar (exact Discipline Core match, non-empty validated elective pool, clean validator run) that `cse`/`eee` were held to — not added as placeholders to hit a scope target.
